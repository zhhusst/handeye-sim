# 线激光双边角点自动手眼标定与精密球评价操作指南

版本：2026-08-20  
适用对象：FANUC M-20iD/25、R-30iB、Gocator二维轮廓仪、`PC_TRACK_ALL`、当前ROS 2真机系统。

本指南给出一次完整实验的标准流程：

```text
实验准备
→ 启动真机环境
→ 初始ROI对齐
→ 自动采集6个种子位姿
→ 12-DOF-V2共享形貌初始化
→ 主动NBV采集与滚动求解
→ 保存完整标定数据
→ 7方向精密球移动扫描
→ 评价方法1与评价方法2
→ 数据完整性检查与实验登记
```

## 1. 必须遵守的实验约束

1. 真机自动运动前，示教器必须运行 `PC_TRACK_ALL`，程序指针已经进入循环。
2. `UFRAME_NUM=1`、`UTOOL_NUM=1`，开始前 `R[100]=0`。
3. 使用T1和低速模式，人员离开机器人运动范围，并可随时使用HOLD或急停。
4. 标定过程中不得改变Gocator相对法兰的机械安装。
5. 一次精密球扫描中，球和球座必须完全固定。
6. 精密球数据只用于独立评价，不能反过来优化本次手眼结果。
7. 正式评价方法2必须保留7个合格扫描方向。4～6方向只能作为故障诊断。
8. 出现覆盖、回头、姿态漂移等警告时，正式实验不得强制保留该方向。

## 2. 实验前准备

### 2.1 硬件准备

- 检查Gocator、法兰连接件、线缆和标定物是否松动。
- 建议Gocator预热后再开始批量实验，并在整组实验中保持曝光和测量配置不变。
- 平板应固定在工作台上，目标板角的两条物理边无遮挡。
- 示教器确认 `UF=1`、`UT=1`，关节角与RViz机器人姿态大致一致。
- 自动运动前确认 `PC_TRACK_ALL` 正在循环等待。

### 2.2 软件构建

代码或ROS包发生变化后执行：

```bash
cd /workspace
./scripts/build.sh
```

仅修改Python脚本或当前真机YAML参数时通常不需要重新构建，但必须重新启动相应程序。

## 3. 两个终端启动真机系统

### 3.1 终端1：启动FANUC、Gocator、MoveIt和RViz

完整自动标定需要运动写权限：

```bash
cd /workspace
./scripts/start_environment.sh real --motion-mode automatic
```

启动后的正常状态应为：

```text
motion_mode=automatic
运动桥具备写权限
启动状态为DISARMED
```

`DISARMED`是正确的安全状态。只有在终端2输入大写 `ARM` 后才会临时解锁；流程结束或异常退出时会自动撤防。

### 3.2 终端2：开启激光

```bash
source /opt/ros/jazzy/setup.bash
source /workspace/ros2_ws/install/setup.bash

ros2 service call /gocator/set_laser_state \
  gocator_msgs/srv/SetLaserState \
  "{enable: true}"
```

### 3.3 可选的测量链检查

```bash
ros2 service call /gocator_metric_adapter/status \
  std_srvs/srv/Trigger '{}'

ros2 service call /measurement_sync/status \
  std_srvs/srv/Trigger '{}'

ros2 service call /profile_endpoint_detector/status \
  std_srvs/srv/Trigger '{}'

ros2 service call /fanuc_motion_bridge/status \
  std_srvs/srv/Trigger '{}'
```

开始标定前应确认：

- Gocator轮廓消息持续增加；
- 同步轮廓持续增加，`last_error`为空；
- 机器人停止时速度接近0；
- 断点检测能够进入 `VALID/SAFE`；
- 运动桥为 `automatic`、`writes=true`、`DISARMED`。

## 4. 执行一次完整自动标定

### 4.1 启动交互控制台

在终端2执行：

```bash
cd /workspace
./scripts/start_calibration.sh --backend real
```

选择：

```text
1. 新建标定：自动采集6个种子位姿
```

程序随即建立独立运行目录：

```text
/workspace/data/calibration_runs/<时间>/
```

并在机器人运动前启动全过程MCAP记录。记录器启动失败时，本次实验会拒绝开始，避免产生没有原始证据的标定结果。

### 4.2 选择动态实测预检模式

推荐正式实验选择：

```text
1. auto
```

- `auto`：静态余量不足时执行动态预检，推荐用于批量实验。
- `always`：每次都执行，更保守但耗时更长。
- `off`：只适用于明确的消融或故障诊断，不建议作为默认论文实验设置。

同一组对比实验必须使用相同预检模式。

### 4.3 在RViz中设置初始位姿

RViz标记含义：

- 黄色：Gocator原始二维轮廓；
- 紫色：期望线和矩形ROI；
- 绿色：实际识别的目标平板表面；
- 两个断点标记：当前锁定的目标板角两条边交点。

使用示教器低速移动机器人，使绿色平板截面与紫色期望区域对齐。当前正式初始软包络为：

- `|x_mid| ≤ 10 mm`；
- `80 mm ≤ z_mid ≤ 450 mm`；
- 断点间轮廓长度为70～90 mm；
- 双边有效且位于安全域；
- 机器人静止；
- 局部IK检查通过。

终端操作：

```text
r      刷新检测状态
Enter  确认当前初始位姿
q      取消
```

不要只看“检测到双边”，必须确认“初始工作包络：通过”。

### 4.4 自动采集6个种子位姿

确认以下条件：

```text
PC_TRACK_ALL正在循环
UF/UT=1/1
R[100]=0
T1/低速
人员离开运动范围
```

在终端输入大写：

```text
ARM
```

当前真机种子目标旋转为10°。系统会自动执行小步旋转、双特征伺服、双边验证、回退和每位姿多帧静止采集。

成功后重点检查种子摘要：

- 物理位姿数量为6；
- 同步观测总数符合配置；
- 六个标签完整；
- 最小两两旋转间隔合理；
- 旋转激励Gram矩阵没有明显退化。

主要文件：

```text
seeds.json
seed_collection.log
```

### 4.5 执行主动NBV标定

六种子完成后，真机运动桥会先撤防。终端会重新显示安全确认，再询问是否开始主动标定。

NBV预算含义：

- `0`：自适应停止，内部仍保留20个NBV紧急保护；
- `1～20`：限制本次最多执行的NBV数量。

建议：

- 新硬件状态或首次验证：先使用1～3个NBV；
- 系统稳定后的完整运行：使用预先规定的固定预算或 `0` 自适应停止；
- 论文对比实验：所有重复实验必须采用相同预算策略，不能根据结果临时改变。

再次输入大写 `ARM` 后，系统执行：

```text
共享形貌12-DOF-V2初始化
→ 候选生成与预测
→ 信息增益评分
→ MoveIt检查
→ 真机执行
→ 双边验证
→ 滚动求解
→ 自适应停止或达到预算
```

最终文件：

```text
calibration_result.json
active_calibration.log
```

真机没有手眼真值，因此终端中的协方差、条件数和留出帧是内部诊断，不等于真实旋转/平移误差。最终精度必须通过独立标定球实验评价。

```text
status = finalized

```

## 6. 采集评价方法2的精密球数据

### 6.1 更换标定物

标定结束并撤防后：

1. 移走平板，牢固安装精密球；
2. 不得改变Gocator相对法兰安装；
3. 球和球座在整个球实验中不能移动；
4. 激光应只选择球面圆弧，避免球杆、底座和工作台进入同一候选段；
5. 精密球采集只观察，不会向机器人发送运动命令，所有移动由示教器完成。

当前Ø20.002 mm球参数：

```text
sphere_20mm
参考半径 = 10.001 mm
```

### 6.2 启动7方向人工移动扫描

可以在标定控制台选择菜单5，也可以直接运行：

```bash
cd /workspace

./scripts/start_sphere_validation.sh \
  --mode moving \
  --result /workspace/data/calibration_runs/你的运行目录/calibration_result.json \
  --sphere sphere_20mm \
  --poses 7 \
  --positions 7 \
  --frames 20
```

正式方法2的数据规模为：

```text
7个不同机器人方向
× 每方向7个平移位置
× 每位置20个静止同步帧
= 980帧
```

### 6.3 每个方向的操作

每个方向遵循以下过程：

1. 设置新的机器人姿态；
2. 将激光切到球面一侧，形成较短但完整的圆弧；
3. 停稳后按Enter，采20帧；
4. 保持姿态不变，只沿同一方向平移约2～4 mm；
5. 再次停稳并采20帧；
6. 重复到第7个位置，使激光跨过近球心截面并到达另一侧。

理想弦长序列为：

```text
短 → 逐渐变长 → 最大 → 逐渐变短
```

例如：

```text
10 → 15 → 19 → 20 → 18 → 14 → 9 mm
```

同一方向内只能平移，不能转动机器人姿态。完成一个方向后，才可以改变姿态开始下一方向。不同方向建议至少相差15°，并覆盖多个明显不同的观察方向。

交互命令：

```text
Enter  采集当前位置
u      撤销上一位置
d      丢弃并重采当前整个方向
r      重看提示
q      取消实验
```

### 6.4 自动质量门限

程序检查：

- 单步平移1～7 mm；
- 每方向总行程12～30 mm；
- 最大轨迹偏线不超过2 mm；
- 方向内姿态漂移不超过0.25°；
- 不同扫描方向的旋转间隔至少15°；
- 每个位置中位弦长至少8 mm；
- 每个位置中位圆拟合RMS不超过0.15 mm；
- 起点和终点相对最大弦长均至少下降2 mm。

正式数据原则：

- 任一方向出现“回头”“总行程不足”“没有短→长→短”“方向过近”时，选择不保留并重采；
- 不要为了尽快完成而强制保留警告方向；
- 7个方向全部合格后才形成正式方法2数据。

保存目录：

```text
/workspace/data/sphere_validation_runs/<时间>_sphere_20mm/
```

主要文件：

```text
sphere_acquisition.npz
metadata.json
sphere_validation_report.json
sphere_validation_report.md
```

其中：

- `frame_pose_indices`记录每帧所属扫描方向；
- `frame_position_indices`记录每帧所属方向内平移位置；
- `metadata.json`冻结手眼矩阵、标定结果路径和SHA256；
- `direction_summaries`记录行程、姿态漂移、直线度和弦长序列。

采集结束时控制台自动打印的是固定半径/自由半径综合验证，即下文评价方法1的核心口径；评价方法2需要单独执行一键脚本。

## 7. 使用球数据评价标定结果

### 7.1 评价方法1：固定半径、自由半径和留一方向

```bash
python3 /workspace/paper_test/评价方法1/eval_two_handeyes.py \
  --result /workspace/data/calibration_runs/你的运行目录/calibration_result.json \
  --npz /workspace/data/sphere_validation_runs/你的球运行目录/sphere_acquisition.npz \
  --radius 10.001 \
  --out /workspace/data/sphere_validation_runs/你的球运行目录/eval_initial_vs_final.json
```

该脚本同时评价：

- 六种子共享形貌初值；
- NBV结束后的最终手眼结果。

重点指标：

- 固定已知半径的全点RMSE；
- 固定已知半径的P95绝对径向误差；
- 自由拟合直径误差；
- 留一方向held-out RMSE；
- 留一方向球心扩散。

### 7.2 评价方法2：ROR和RCIM风格逐方向球拟合

```bash
./scripts/eval_ball.sh \
  --npz /workspace/data/sphere_validation_runs/你的球运行目录/sphere_acquisition.npz \
  --result /workspace/data/calibration_runs/你的运行目录/calibration_result.json \
  --radius 10.001 \
  --z-gate 25 \
  --out /workspace/data/sphere_validation_runs/你的球运行目录/rcim_eval
```

输出：

```text
rcim_eval/
├── validation/scanner1/pose1.csv ... pose7.csv
├── metrics.txt
├── eval_summary.txt
├── Fig15_sphere_validation.png
└── Fig15_beautiful.png
```

评价方法2重点查看：

- 每个方向独立拟合半径 `r_fit`；
- 每个方向半径误差 `delta_r`；
- 每个方向球面残差标准差 `sigma_fit`；
- 合并拟合半径和半径误差；
- 合并径向标准差 `sigma_e`；
- 合并固定名义半径径向RMSE。

ROR默认深度门限为25 mm。正式对比中必须固定该门限，并报告剔除的方向、帧号和数量，不能根据最终误差反复调门限。

### 7.3 结果判读

当前配置的严格检查阈值为：

| 指标 | 阈值 |
|---|---:|
| 独立方向数量 | 至少7 |
| 固定半径全点RMSE | ≤0.100 mm |
| 固定半径P95 | ≤0.200 mm |
| 自由拟合直径误差绝对值 | ≤0.100 mm |

注意：

1. 标定球评价反映点云重建的一致性和尺度误差，不能唯一分离成手眼旋转误差和手眼平移误差。
2. 求解器内部预测的旋转/平移标准差不是独立真机精度。
3. 所有方向半径同号偏差通常提示系统误差，而不是单纯随机噪声。
4. 单个方向明显恶化时，先检查该方向的轨迹、覆盖和圆拟合RMS。
5. 删除坏方向后的结果只能作为归因诊断，不能代替预先规定的7方向正式实验。

## 8. 批量实验建议

### 8.1 一次实验的最小闭环

```text
一个预先定义的初始位姿条件
→ 一次完整自动标定和MCAP
→ 一个冻结的calibration_result.json
→ 一次独立7方向球扫描
→ 方法1结果
→ 方法2结果
→ 实验记录表一行
```

### 8.2 保证公平比较

- 预先规定初始位姿集合、NBV预算、预检模式和停止条件；
- 同组实验使用同一块平板、同一个球和相同Gocator设置；
- 不因某次结果较差而临时增加NBV或修改ROR门限；
- 失败运行也要保留运行目录、日志和MCAP，并记录失败阶段；
- 区分流程成功率、耗时、种子初值精度和NBV最终精度；
- 报告中同时给出中位数、均值、标准差、P95和失败率，不只报告最好的一次。

如果传感器安装、机器人模型、Gocator尺度或曝光发生变化，旧球数据不能直接作为新安装状态的独立评价数据。

## 9. 常见问题

### 9.1 控制台提示运动桥只规划不执行

重新启动终端1：

```bash
./scripts/start_environment.sh real --motion-mode automatic
```

### 9.2 没有同步轮廓

依次检查：

```bash
ros2 service call /gocator_metric_adapter/status std_srvs/srv/Trigger '{}'
ros2 service call /measurement_sync/status std_srvs/srv/Trigger '{}'
```

确认激光已开启、机器人已经停稳、轮廓与关节消息都在增长。

### 9.3 初始断点识别失败

- 将平板表面轮廓移动到紫色ROI；
- 确认绿色选中线段来自平板表面而不是侧壁或工作台；
- 重新调用检测器复位后再对齐；
- 一次只做小幅调整。

### 9.4 精密球某方向无法形成短→长→短

- 回到该方向球面一侧重新开始；
- 保持姿态不变；
- 选择真正使激光平面跨过球体的平移方向；
- 每次移动2～4 mm；
- 使用 `d` 丢弃并重采当前方向。

### 9.5 完整记录异常

检查：

```text
recording_manifest.json
full_run_recording.log
full_run_bag/metadata.yaml
full_run_bag_info.txt
```

记录未完成的实验不得作为正式统计样本，但应作为系统失败率样本登记。

## 10. 实验结束

确认运动桥已撤防，然后关闭激光：

```bash
ros2 service call /gocator/set_laser_state \
  gocator_msgs/srv/SetLaserState \
  "{enable: false}"
```

最后停止终端2控制台和终端1环境。停止前确认所有MCAP已经显示“保存并通过索引检查”。
